# Hermit 単体テスト拡充

Hermit の既存実装を根拠に、`test/` の Google Test を拡充する。対象は公開され再利用可能な関数、クラス、設定型、parser の AST／評価 visitor、filesystem・文字列・ネットワーク補助・生成バックエンドの純粋な変換処理とする。外部サーバー、実ネットワーク、ユーザー環境へ依存する処理は、境界をモック可能にする変更なしにテストへ持ち込まない。

## 手順

1. `AGENTS.md`、`SPECIFICATION.md`、`test/test.cpp`、既存テスト、公開ヘッダーを確認する。`third_party/` と `vcpkg_installed/` は閲覧・検索・編集・検証の対象外とする。
2. 公開宣言と実装から未テストの関数・クラス・分岐を一覧化し、正常系、境界値、エラー系、状態遷移の順に優先順位を付ける。既存テストとの重複は避ける。
3. テストは `test/test.cpp` または責務に対応する `test/*.cpp` に追加し、Google Test の既存規約に合わせる。テスト専用の実装取り込み構成（`test/Hermit.cpp`）を壊さない。外部 I/O は一時ファイル、インメモリ入力、依存注入または決定的なスタブで隔離する。
4. 公開 API の仕様・エラー型・戻り値・副作用を実装と照合し、テスト名から検証内容が分かるようにする。ランダム値、時刻、環境変数、プロセス、ネットワークは決定性を確保する。
5. テスト追加に伴い `SPECIFICATION.md` のテスト構成・検証対象・テスト数の記述が変わる場合は同じ変更で更新する。公開仕様や実行方法を変更した場合は `readme.md` も更新する。
6. Visual Studio 18 Developer 環境を `VsDevCmd.bat -arch=x64 -host_arch=x64` で初期化し、まず差分の `Release|x64` ビルド（`/t:Build`）を実行する。ツールチェーン変更、生成先変更、依存関係破損、クリーン状態の再現が必要な場合だけ `/t:Rebuild` を使用する。PDB を無効化して失敗を隠さず、C1902/LNK1101 はツールチェーン・中間ディレクトリ・PDB パスを調査する。
7. `hermit-build-test` の手順に従って `test.exe` を実行し、テスト別出力と終了コードを確認する。失敗時はテスト名、再現条件、診断を記録する。

## 完了条件

- 公開 API の未テスト領域を確認し、追加したテストが実装の実際の契約を検証している。
- テストが決定的で、外部ネットワーク・常駐プロセス・ユーザー環境に依存しない。
- `test.vcxproj` の Release x64 ビルドと `test.exe` が成功し、終了コード 0 である。
- テスト数、対象範囲、実行方法がコード・`SPECIFICATION.md`・必要に応じて `readme.md` と一致している。
- 追加テスト後も既存テストがすべて成功し、失敗を無視したまま完了扱いにしない。
