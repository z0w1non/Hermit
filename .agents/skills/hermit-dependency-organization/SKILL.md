# Hermit 依存関係整理

Hermit のコードを機能・責務単位に整理し、疎結合、高凝集、情報隠蔽、差分ビルドの効果を高める。`third_party/` と `vcpkg_installed/` は閲覧・検索・編集・検証の対象外とする。

## 手順

1. `rg --files` で `Hermit/`、`test/`、プロジェクト設定、`readme.md`、`SPECIFICATION.md` を確認し、対象ファイルの一覧を作る。単一ファイルだけを対象にして完了扱いにしない。
2. 対象 `.cpp` の実際のシンボル使用と責務を調べ、不要な推移依存を排除した直接依存を特定する。巨大な統合ヘッダーは避け、機能別の公開ヘッダーまたは非公開実装へ置き換える。
3. 高凝集になる責務単位（共通型・例外・設定・AST・parser・filesystem・network・backend など）を抽出する。分割はファイル数を増やすこと自体を目的にせず、変更理由、依存方向、再利用境界、コンパイル単位が明確になる粒度とする。
4. 共通型、例外、設定型、AST、Boost 適応定義を循環参照なしに分離する。テンプレート定義と Boost ヘッダーは利用箇所のヘッダーまたは実装へ限定する。
5. 不足依存をコンパイラーエラーから補完する。推測で包括ヘッダーを戻さず、追加した直接依存を `.cpp` の先頭へ記述する。
6. `.vcxproj` と `.filters` に新規ファイルを登録し、XML を検証する。
7. `SPECIFICATION.md` のファイル一覧と Make 形式の依存関係（`target: dependency...`）を同じ変更で更新する。コードと資料の記述を照合する。
8. `Release|x64` の差分ビルド（`/t:Build`）を優先して実行する。`/t:Rebuild` はツールチェーン変更、生成先変更、依存関係破損、クリーン状態の再現が必要な場合に限定し、理由を記録する。MSBuild が PATH にない場合は Visual Studio の `MSBuild.exe` を明示指定し、PDB/ツールチェーンエラーとソースエラーを分けて報告する。並列ビルドを使う場合も、開始時のセッション ID を保持し、少なくとも 10 秒以内の間隔で出力・実行状態・終了コードを取得する。
9. 1 回の変更後も未整理の `.cpp`、巨大ヘッダー参照、循環依存、推移依存が残っていないかプロジェクト全体を再走査し、次のファイル群へ進む。少なくとも複数の独立した責務単位を反復して確認する。
10. ビルド可能な状態になったら、既存の `hermit-build-test` スキルに従って `test.exe` を実行する。

## 完了条件

- 各変更対象 `.cpp` が責務に対応する直接ヘッダーだけを参照し、巨大な統合ヘッダーへの不要な依存を持たない。
- プロジェクト全体を再走査しても整理対象が残っていない、または各残存依存について「疎結合化の利点がない」「公開境界の再設計が必要」「解決不能なビルド阻害」といった理由を記録できるまで完了としない。
- 分割後も責務が高凝集で、依存方向が一方向、循環依存がなく、公開面が必要最小限になっている。
- `.vcxproj`、`SPECIFICATION.md`、実装の依存関係が一致している。
- ビルド・テスト結果、または環境上の阻害要因を報告できる。
- バックグラウンド処理を未確認のまま放置せず、完了・失敗・継続中のいずれかをチャット上で確認できる。
