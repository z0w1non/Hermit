# Hermit 依存関係整理

Hermit のコードを疎結合・高凝集に整理する。巨大な統合ヘッダーを減らすこと自体ではなく、変更理由、責務、依存方向、コンパイル単位が一致する分割を目指す。

## 手順

1. `AGENTS.md`、`docs/REQUIREMENTS.md`、`docs/ISSUES.md`、`docs/SPECIFICATION.md` を読み、制約と関連課題を確認する。依頼が開発継続や課題解決を含む場合は、要求から作業計画を立てる。要求本文は明示指示なしに変更しない。
2. `rg --files` で `Hermit/`、`test/`、各 `.vcxproj` / `.filters` と関連資料を一覧化する。`third_party/` と `vcpkg_installed/` は閲覧・検索・編集・検証の対象外とする。
3. 対象 `.cpp` のシンボル使用と責務を調べ、不要な推移依存を除いて必要な直接依存を特定する。標準、外部、プロジェクト、Windows 系の include 順を守る。
4. 必要な場合に限り共通型、例外、設定、AST、parser、filesystem、network、backend 等を責務単位に分割する。循環参照を避け、公開面を必要最小限にし、テンプレート定義や Boost 依存を実際の利用境界に置く。
5. 不足依存はコンパイラー診断とシンボル利用から補う。推測で包括ヘッダーを戻さない。新規ファイルは `.vcxproj` と `.filters` に登録し、XML を確認する。
6. `docs/SPECIFICATION.md` のファイル構成表とヘッダー依存関係表を更新し、実装・プロジェクト設定・資料を照合する。
7. プロジェクト全体を再走査し、独立した複数の責務領域について未整理依存、循環、不要な集約ヘッダー参照が残るか確認する。残存項目は利点がない理由、必要な設計判断、または阻害要因を記録する。
8. 変更後のビルド・テストが依頼された場合、または作業上必要な場合は `hermit-build-test` に従って Release x64 の差分ビルドとテストを実行する。再ビルドを使う場合は理由を記録する。

## 完了条件

- 変更した実装が責務に対応する直接依存だけを持ち、循環依存がない。
- 分割が凝集性、情報隠蔽、依存方向を改善し、ファイル数だけを増やしていない。
- `.vcxproj`、`.filters`、`docs/SPECIFICATION.md` と実装が一致している。
- プロジェクト全体を再走査し、残る整理対象とその理由を説明できる。
- 実行した検証の結果、または実行できなかった理由を報告できる。
