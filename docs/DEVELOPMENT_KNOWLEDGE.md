# 開発知見台帳

本書は、実装・調査・テストで得た再利用可能な知見と、その根拠を表形式で管理します。仕様の規範は `SPECIFICATION.md`、課題の優先順位と状態は `ISSUES.md`、構文の段階と公開方針は `MACRO_PARSER_REDEVELOPMENT.md` を参照してください。本書は観測事実、採否、再現手順を記録し、これらの文書を置き換えません。

## 記録方法

各行を独立した知見として識別し、再現条件、実測した結果、結論、適用範囲、証拠を一緒に残します。成功・失敗の試行を区別し、仮説を確定事項として扱いません。新しい検証で結論が変わった場合は既存行を消さず、状態と根拠を更新して経緯を追えるようにします。

ID は `<分野>-<対象>-<3桁連番>` 形式とし、分野接頭辞で知見の種類を示します。現在は Qi (`QI`)、評価 (`EVAL`)、依存性注入 (`DI`)、ビルド (`BUILD`) を使います。連番は台帳全体で一意にし、並び替えや追記後も既存IDを変更・再利用しません。別資料から参照する場合は完全なIDを記載します。

| 列 | 記録する内容 | 設計理由 |
| --- | --- | --- |
| ID | 変更されない知見識別子 | 課題表やコードレビューから参照しやすくする。 |
| 分野・対象 | parser属性、評価、依存注入など | 関連する知見を絞り込む。 |
| 問い・前提 | 解決しようとした不確実性と対象境界 | 試行が何を判断するものか明確にする。 |
| 再現条件・操作 | 最小入力、AST型、callback設定、ビルドflagなど | 同じ実験を再実行できるようにする。 |
| 観測 | parse/AST/評価結果、診断、状態変化 | 解釈と生データ相当の事実を分ける。 |
| 結論・採否 | 採用した設計、棄却理由、保留判断 | 次の実装者が同じ失敗を繰り返さないようにする。 |
| 適用範囲・制約 | 成立するgrammar・構成と未解決境界 | 過剰な一般化や誤った公開を防ぐ。 |
| 根拠・検証 | ソース、テスト名、構成、件数、課題リンク | 結論をコードと実行結果までたどれるようにする。 |
| 状態・次の行動 | 確定／棄却／暫定／未検証と、必要なら次の実験 | 知見の確度と未完了作業を明確にする。 |
| 更新日 | 最後に根拠または結論を確認した日 | 古い環境・構成の結果を見分ける。 |
