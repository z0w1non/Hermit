# 宣言的要求仕様

この文書は Hermit のユーザー承認済み要求を記録する正本です。要求は達成すべき状態と受け入れ条件を表し、実装方法や作業順を固定しません。エージェントはこの要求を根拠に調査・計画し、依存順に実装・検証します。

## 記載・変更ルール

- ユーザーは要求をこの文書へ直接記載できます。または、追加・変更・削除する要求IDと変更内容を明示してエージェントへ更新を指示できます。
- エージェントはユーザーの明示的な記載または更新指示なしに、要求を追加・変更・削除・要約し直して規範的内容を変えてはいけません。実装上の発見や改善提案は `docs/ISSUES.md` または計画資料に記録します。
- 要求文の更新指示が曖昧で、目的・振る舞い・受け入れ条件が変わり得る場合は、該当点を確認してから要求本文を更新します。
- 要求の識別子は安定して維持します。削除または置換の指示があった要求も、追跡が必要な場合は履歴表へ移し、根拠なく再利用しません。
- 要求IDは種類接頭辞 `REQ-` と3桁以上の連番で構成します。IDは順序・優先度を示さず、要求の追加や並び替えでも既存IDを変更しません。
- 要求の優先度、状態、実装状況、対応する課題ID、検証結果は、要求本文と分けて管理します。要求文の状態更新は規範的内容を書き換えないメタデータ変更として扱います。

## 要求の形式

要求は次の項目を基本とします。ユーザーが簡潔な文章のみを指定した場合は意味を変えずに記載し、未指定の条件を推測で補いません。

```text
### REQ-NNN: 短い名称

- 目的: 利用者またはプロジェクトに必要な結果
- 要求: システムが満たすべき振る舞い・制約
- 受け入れ条件: 要求を満たしたと判断できる観測可能な条件
- 範囲・制約: 必要な場合のみ記載
```

## 承認済み要求

### REQ-001: 宣言的要求に基づく自律開発計画

- 目的: ユーザーが定めた要求に沿って、Hermit の開発作業を自律的に計画・実行できるようにする。
- 要求: 宣言的要求は本資料を正本とし、ユーザーが直接記載するか、要求資料の更新を明示的に指示した場合にのみ追加・変更する。エージェントは要求と課題・実装状況を照合して依存順の計画を作り、要求本文を改変せずに実装・検証する。
- 受け入れ条件: `AGENTS.md` が要求資料の正本、更新権限、計画手順、矛盾時の扱いを定めている。本資料が要求の記載形式と進捗対応欄を提供する。要求変更の明示的指示なしにエージェントが要求本文を作らない。
- 範囲・制約: この要求は開発作業の進め方を定める。製品の機能要求はユーザーが別途記載または更新指示した時点で登録する。

### REQ-002: 差分ビルドを基本とするビルド高速化

- 目的: 通常の変更で必要な範囲だけを再ビルドし、ビルド待ち時間を継続的に減らす。
- 要求: ファイル分割、疎結合、適切な抽象化、Pimpl パターンなどを用い、差分ビルドを基本としてビルド全体を高速化する。
- 受け入れ条件: 変更理由とコンパイル単位が適切に対応し、通常の変更で不要な翻訳単位の再ビルドを避ける。変更前後のビルド時間と再コンパイル範囲を、同一条件で比較可能な場合は記録する。
- 範囲・制約: PDB、LTCG、デバッグ情報など必要な成果物・品質設定を無効化して短縮してはならない。設計上の複雑さや保守コストを考慮し、抽象化は効果が見込める境界に適用する。

### REQ-003: 依存性注入を基礎とした単体テスト網羅

- 目的: 外部環境に依存する経路を含め、単体テストで確認できる振る舞いを広く決定的に検証する。
- 要求: 依存性の注入を基本とし、外部サービス、OS、ネットワーク、プロセス、ファイルシステムなどを差し替え可能にして、単体テストで検証可能な範囲を最大限網羅する。
- 受け入れ条件: 新規・変更した再利用可能な処理と注入可能な境界について、該当する正常系、境界値、失敗系を単体テストで検証する。実環境を要する確認は単体テストと区別して記録する。
- 範囲・制約: テストのためだけに過剰な抽象化を導入せず、既定の製品動作と公開 API 互換性を維持する。

### REQ-004: 資源観点を含む開発ボトルネックの継続分析

- 目的: 限られた開発資源を有効に使い、開発と検証の効率を高める。
- 要求: 開発のボトルネックを、時間をはじめとするあらゆる資源の観点から適宜分析し、根拠に基づいて効率化する。
- 受け入れ条件: 作業計画や反復で顕著な遅延・無駄・資源制約が見られる場合、その影響と測定可能な根拠を確認し、効果に見合う改善を優先する。計測結果と改善後の影響を比較できる場合は記録する。
- 範囲・制約: 時間、CPU、メモリ、ストレージ、ネットワーク、作業者の手戻りなど、対象に応じた資源を扱う。改善は正確性、安全性、保守性、ユーザー要求を損なわない範囲で行う。

### REQ-005: 対象バックエンド Web API の完全サポート

- 目的: Hermit から対象バックエンドが提供する Web API の全機能を利用できるようにする。
- 要求: 対象とするバックエンドが提供する全てのWeb APIをサポートする。
- 受け入れ条件: 対象バックエンドごとに公式資料で公開 API の操作、method、path、入力、出力を棚卸しし、Hermit の実装と回帰テストを各操作へ対応付ける。未対応操作が残る間は完了と判定しない。
- 範囲・制約: 対象は `tg`（Text Generation Web UI）、`kc`（KoboldCpp）、`sd`（Stable Diffusion WebUI）、`sb`（Style-Bert-VITS2）、`cu`（ComfyUI）、`lmstudio`（LM Studio）、`llama-cpp`（llama.cpp server）、`vllm`（vLLM）、`ollama`（Ollama）の各 Web API とする。対象ソフトウェアの API バージョン・拡張機能による差異は公式資料の根拠とともに記録する。
